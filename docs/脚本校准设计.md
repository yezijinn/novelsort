# 脚本校准设计

## 目标

在确定性切分之后，按章校准：

- 说话人
- 情绪
- 语气

只改标签，不改原文、不改片段边界。

## 现有基础

- 每章独立缓存，可按章发送、按章重试、按章回退。
- 片段已有 `speaker_id`、`speaker_hint`、`emotion`、`tone`、`confidence`、`needs_review`。
- 章节列表可显示校准状态，不依赖整本一次性处理。

## 可参考的本地项目

| 项目 | 可借鉴 |
|---|---|
| `novelstruct` | 单章分块、角色表、断点续跑、JSON 校验、原文覆盖校验 |
| `novel-lines` | 两层文档结构、角色与对话对象、保真校验 |
| `alexandria` | `speaker/text/instruct` 脚本、旁白与角色分离、音色分配 |
| `novel2voice` | 音色目录、角色与情绪标签、批量生成流程 |

`novelstruct` 为 GPL-3.0，可直接参考实现。
`novel-lines` 与 `novel2lines` 没有许可证文件，只参考字段设计。
`alexandria` 为 MIT，`novel2voice` 为 Apache-2.0。

## 请求设计

每章单独发请求：

- 片段：`id`、`type`、`text`、`speaker_hint`
- 角色表：规范名、别名、性别、是否旁白
- 上下文：上一章末尾若干段、下一章开头若干段
- 系统指令：只输出 JSON；不得改写原文；无法确定用“未知角色”；无依据的情绪/语气用 null

响应只回标签：

```json
[
  {"id": 12, "speaker": "林雪", "emotion": "cold", "tone": "low"},
  {"id": 13, "speaker": "未知角色", "emotion": null, "tone": null}
]
```

程序按 `id` 合并，不接收响应里的正文。
响应必须覆盖本章所有对白与心声；缺失或重复即判失败。

## 校验

- `id` 必须存在且唯一。
- 说话人必须在角色表中，或作为新角色登记。
- 情绪/语气允许开放集合，空值写 null。
- 只更新标签字段；原文、偏移、类型不变。
- 任一条失败：整章回滚，保留旧结果，记录错误。
- 重试有限次；失败章节可单独重跑。

## 角色表

- 规范名 + 别名 + 性别 + 是否旁白。
- 跨章复用，避免同一角色多种称呼。
- 同名归一化；别名合并；冲突时以用户确认结果为准。
- 无法确定时保留“未知角色”，不强行猜测。

## 缓存与状态

每章保存：

- 源文本哈希
- 指令版本
- 接口与配置标识
- 响应 JSON
- 校准时间
- 校验结果

章节列表显示：未校准 / 已校准 / 需复核 / 失败。
源文本、指令或配置变化时，对应章缓存失效。

## 界面

- 章节列表显示校准状态。
- “校准本章”处理当前章。
- “校准未完成章节”按顺序批处理，可暂停/继续。
- 表格增加情绪、语气列；详情显示校准前后差异。
- 支持接受/拒绝单条或整章结果。

## 接口与配置

- 兼容 `chat/completions` 的 HTTP 接口。
- 地址、服务标识、密钥、温度、超时、最大输出均可配置。
- 优先使用结构化输出；不支持时用 JSON 模式并在本地校验。
- 本地接口优先；云端接口需明确提示文本会上传。
- 密钥只从环境变量或本地设置读取，不写入日志、导出文件或仓库。

## 分块

- 默认一章一请求。
- 超过上限时按场景/段落切块，携带角色表和前后文。
- 块之间保留重叠上下文，合并时按 `id` 去重。
- 失败只重跑当前块，不重跑整章。

## 与语音合成的衔接

校准后的章节可导出：

- `speaker_id`
- `emotion`
- `tone`
- `voice_id`
- `speak_text`
- `pause_after_ms`

音色映射独立于校准；换音色不触发重新校准。
